# 用户管理

## 背景
管理员需要查看所有注册用户，并能禁用违规账号、恢复误禁账号。

## 用户故事
- 作为管理员，我想要分页浏览和搜索所有用户，以便快速找到某个人
- 作为管理员，我想要禁用 / 启用用户，以便阻止违规账号登录
- 作为被禁用的用户，我想要登录时看到明确的原因，以便知道不是密码错了

## 前置条件
- 模块 01 已完成（`adminProcedure`、后台 layout）

## 验收标准
### 列表
- [ ] AC1：给定管理员访问 `/dashboard/users`，那么表格显示每个用户的名字、邮箱、角色、状态（正常 / 已禁用）、注册时间，按注册时间倒序
- [ ] AC2：给定用户数超过 20，那么每页显示 20 条，有上一页 / 下一页和"第 X / Y 页"，翻页后 URL 带 `page` 参数，刷新后仍停在该页
- [ ] AC3：给定已有用户 `Alice <alice@test.local>`，当搜索 `ALI`、`alice`、`TEST.LOCAL` 中的任一个，那么都能搜到她（名字或邮箱模糊匹配，不区分大小写）
- [ ] AC4：给定在第 3 页时输入搜索词，那么结果从第 1 页开始显示
- [ ] AC5：给定搜索词没有匹配，那么显示"没有找到匹配的用户"空状态；给定系统里没有用户（接口返回空列表），那么显示"暂无用户"空状态

### 禁用 / 启用
- [ ] AC6：给定一个正常用户，当管理员点"禁用"，那么先弹出确认框；点取消则什么都不变，点确认后该行状态变为"已禁用"，按钮变为"启用"
- [ ] AC7：给定一个已禁用用户，当管理员点"启用"并确认，那么状态变回"正常"，该用户可以再次登录
- [ ] AC8：给定一个已禁用用户，当他用正确的邮箱和密码登录，那么登录失败，页面提示"账号已被禁用"
- [ ] AC9：给定用户 A 已在浏览器 X 登录，当管理员禁用 A 后，A 在浏览器 X 刷新页面或发出任意请求，那么 A 被退出登录（需要登录的页面跳到 `/login`）
- [ ] AC10：给定管理员查看列表，那么自己那一行的"禁用"按钮不可点；直接调用接口禁用自己，返回 `FORBIDDEN`，状态不变
- [ ] AC12：给定另一个管理员 C，当管理员禁用 C 并确认，那么操作成功（只限制不能禁用自己）
- [ ] AC11：给定普通用户直接调用 `user.list` 或 `user.setBanned`，那么返回 `FORBIDDEN`
