# GitHub 用户收藏（Web）

## 背景
在 Web 上按用户名查询 GitHub 用户、加入收藏，并在同一个列表页查看、修改备注、删除已收藏的人。数据存在已部署的 AWS HTTP API 里，浏览器直接调用它；调用代码沉淀为 Web 和 React Native 共用的包 `@jax-workflow-project/github-users`。

## 用户故事
- 作为访客，我想要输入 GitHub 用户名查询到这个人的资料，以便决定要不要收藏
- 作为访客，我想要把查询结果添加到收藏列表，以便以后查看
- 作为访客，我想要在收藏列表里修改某个人的备注、删除某个人，以便维护列表

## 前置条件
- AWS API Gateway `jax-gh-api` 已配置 CORS：允许来源 `http://localhost:3001`，允许方法 GET / POST，允许请求头 `content-type`（由用户在 AWS 控制台配置）

## 验收标准
- [ ] AC1：给定存在的 GitHub 用户名（如 `octocat`），当调用共享客户端的 `search`，那么返回该用户的 `githubId`（数字）、`login`、`name`、`avatarUrl`、`followers` 等资料 | 验证: api
- [ ] AC2：给定不存在的用户名，当调用 `search`，那么抛出 `GithubUsersApiError` 且 `status` 为 404；给定非法用户名（含空格或特殊字符、超过 39 位），那么抛出校验错误，并且不发出网络请求 | 验证: api
- [ ] AC3：给定查询到的用户，当调用 `create`，那么 `list` 里出现这个人，`githubId` 是数字、`note` 为空；对同一个人再次 `create` 不会产生重复记录 | 验证: api
- [ ] AC4：给定已收藏的用户，当调用 `update` 设置备注，那么 `list` 里这个人的 `note` 变为新值；传 `null` 时清空备注；对不存在的 `githubId` 调用抛出 `status` 为 404 的 `GithubUsersApiError` | 验证: api
- [ ] AC5：给定已收藏的用户，当调用 `delete`，那么 `list` 里不再有这个人；再删一次抛出 `status` 为 404 的 `GithubUsersApiError` | 验证: api
- [ ] AC6：给定 AWS 原始响应里的 `github_id` 是字符串（如 `"1024025"`），当共享包解析这条记录，那么得到的 `githubId` 是数字 `1024025` | 验证: api
- [ ] AC7：给定从 `http://localhost:3001` 发起的跨域预检请求（`OPTIONS /users/create`，请求方法 POST，请求头 `content-type`），那么 AWS 返回的 `access-control-allow-origin` 是 `http://localhost:3001` | 验证: api
- [ ] AC8：给定打开 `/github`，那么页面顶部是用户名输入框和"查询"按钮，下方是收藏列表；输入框为空时"查询"按钮不可点 | 验证: ui
- [ ] AC9：给定输入存在的用户名并点"查询"（或按回车），那么在输入框下方显示查询结果：头像、用户名、姓名、粉丝数和"添加"按钮 | 验证: ui
- [ ] AC10：给定查询结果，当点"添加"，那么这个人出现在下方收藏列表里，查询结果上的按钮变为"已添加"且不可点 | 验证: ui
- [ ] AC11：给定收藏列表里的某个人，当点"编辑备注"、输入备注并保存，那么列表里显示新备注，刷新页面后备注仍在 | 验证: ui
- [ ] AC12：给定收藏列表里的某个人，当点"删除"并在确认框里确认，那么这个人从列表消失；在确认框里点取消则不删除 | 验证: ui
- [ ] AC13：给定输入不存在的用户名并查询，那么显示"没有找到这个 GitHub 用户"，不显示"添加"按钮 | 验证: ui
- [ ] AC14：给定收藏列表接口返回空列表（测试里拦截浏览器发往 AWS 的 `GET /users/list`，返回 `{"count":0,"users":[]}`），那么收藏列表区域显示"还没有收藏任何人" | 验证: ui
- [ ] AC15：给定接口响应被延迟 3 秒（测试里拦截发往 AWS 的请求后延迟放行），那么：列表加载期间显示加载状态；查询进行中"查询"按钮不可点；添加进行中"添加"按钮不可点；在此期间连续点击多次，`GET /github` 和 `POST /users/create` 各只发出 1 次请求 | 验证: ui
- [ ] AC16：给定输入非法用户名（如 `bad name!`）并点"查询"，那么显示"用户名只能包含字母、数字和连字符，最长 39 位"，浏览器不发出 `GET /github` 请求 | 验证: ui
- [ ] AC17：给定 `GET /github` 返回 429 或 502（测试里拦截返回），那么显示"GitHub 暂时不可用，请稍后再试"；给定 `GET /users/list` 返回 500，那么列表区域显示错误和"重试"按钮，点"重试"后重新请求列表，上方查询区仍可正常使用 | 验证: ui
- [ ] AC18：给定编辑备注时输入超过 1000 字，那么提示"备注最多 1000 字"且不发出 `POST /users/update` 请求；给定把备注改成空字符串并保存，那么 `POST /users/update` 请求体里的 `note` 为 `null`，列表里不再显示备注 | 验证: ui
- [ ] AC19：给定删除时这个人已经被别处删除（`POST /users/delete` 返回 404，测试里拦截返回），那么这个人从列表移除并提示"已被删除" | 验证: ui

## 假设
- 不需要登录：AWS 接口本身是公开的，页面 `/github` 不要求登录
- 浏览器直接请求 AWS（不经过本仓库的服务端），依赖 AWS 侧配置的 CORS；因此不新增 tRPC 接口，这是对"新接口写成 tRPC procedure"约定的有意例外（接口不在本仓库）
- "修改"只修改备注 `note`；GitHub 资料以 GitHub 为准，想更新资料就重新查询后再"添加"（后端会覆盖更新）
- 查询一次只返回一个人（按用户名精确查询），"查询结果列表"就是这一条结果
- 收藏列表按添加时间倒序，最多显示后端返回的 100 条，不分页
- AWS Base URL 写成共享包里的常量，不新增环境变量
- 自动测试会真实读写线上数据：只使用固定的测试账号（如 `octocat`、`github`），测试结束删除自己添加的记录；GitHub 匿名接口每小时 60 次的限流可能导致偶发失败

## 不做的事
- 登录、鉴权、按用户隔离收藏
- 按关键词模糊搜索多个 GitHub 用户
- 批量操作、分页、排序切换
- 修改 AWS 后端或数据库（CORS 由用户在 AWS 控制台配置）
