# GitHub 用户收藏（Android / iOS）

## 背景
和 Web 一样的收藏功能，用 React Native（Expo）一套代码写 Android 和 iOS 双端，直接调用 AWS HTTP API（原生 App 不受 CORS 限制），复用模块 04 的共享包 `@jax-workflow-project/github-users`。

## 用户故事
- 作为手机用户，我想要在 App 里输入 GitHub 用户名查询并收藏，以便随时查看
- 作为手机用户，我想要在 App 的收藏列表里修改备注、删除某个人，以便维护列表

## 前置条件
- 模块 04 已完成（共享包 `@jax-workflow-project/github-users` 的 schema 和客户端）

## 验收标准
- [x] AC1：给定 `apps/native`，当执行 `expo export` 分别打包 `ios` 和 `android`，那么两个平台都成功生成 JS bundle，没有模块解析或编译错误 | 验证: api
- [x] AC2：给定在 iOS 模拟器打开 App，那么首屏顶部是用户名输入框和"查询"按钮，下方是收藏列表；输入框为空时"查询"按钮不可点 | 验证: 人工（需要在 iOS 模拟器里操作原生界面，项目的 Playwright 测试只能驱动浏览器）
- [ ] AC3：给定输入存在的用户名并点"查询"，那么显示查询结果：头像、用户名、姓名、粉丝数和"添加"按钮；查询不存在的用户名时显示"没有找到这个 GitHub 用户" | 验证: 人工（同 AC2）
- [x] AC4：给定查询结果，当点"添加"，那么这个人出现在下方收藏列表，结果卡片按钮变为"已添加"且不可点 | 验证: 人工（同 AC2）
- [x] AC5：给定收藏列表里的某个人，当点"编辑备注"、输入并保存，那么列表显示新备注；下拉刷新或重启 App 后备注仍在 | 验证: 人工（同 AC2）
- [x] AC6：给定收藏列表里的某个人，当点"删除"并在系统确认弹窗里确认，那么这个人从列表消失；点取消则不删除 | 验证: 人工（同 AC2）
- [ ] AC7：给定在 Web 上添加或删除了某个人，当在 App 里下拉刷新收藏列表，那么看到相同的数据 | 验证: 人工（需要同时操作 Web 和 App）
- [ ] AC8：给定在 Android 模拟器或真机上打开 App，那么逐项满足：空输入时"查询"不可点；查询存在的用户显示头像、用户名、姓名、粉丝数和"添加"；查询不存在的用户显示"没有找到这个 GitHub 用户"；点"添加"后出现在列表且按钮变为"已添加"；编辑备注保存后显示新备注；删除弹窗点确认后消失、点取消保留 | 验证: 人工（需要 Android 模拟器或真机）
- [ ] AC9：给定在 iOS 模拟器里，那么逐项满足：输入非法用户名提示"用户名只能包含字母、数字和连字符，最长 39 位"；断网后查询或加载列表提示"服务暂时不可用，请稍后再试"并能重试；请求进行中对应按钮不可点；备注超过 1000 字提示并拒绝保存，保存空字符串后备注被清空；收藏列表为空时显示"还没有收藏任何人"；键盘弹出时输入框和"查询"按钮不被遮挡 | 验证: 人工（需要在 iOS 模拟器里操作原生界面和切换网络）

## 假设
- 用 Expo（当前最新稳定 SDK）+ TypeScript，单屏应用，不引入导航库
- App 不需要登录，直接请求公开的 AWS 接口，Base URL 用共享包里的常量
- 交互、文案和空状态与 Web 保持一致；删除确认用系统原生弹窗
- 只做开发构建（Expo Go / 模拟器运行），不做上架打包、签名和应用图标设计

## 不做的事
- 上架 App Store / Google Play、签名、推送通知
- 离线缓存、深色模式之外的主题定制
- 登录和鉴权
